# Логика расчёта дат этапов релиза

Конфигурация этапов и правил: `src/config/scheduling.ts`  
Изолированный расчёт: `src/services/scheduling/calcSchedule.ts`

## Ключевые даты релиза

| Код | Смысл | Совпадает с этапом |
|-----|--------|-------------------|
| FF | Feature freeze — передача сборок на тест | FF |
| CF | Code freeze | ZNI_DOCS |
| ZNI | Заведение ЗНИ (упрощённо — этап ZNI_INIT в цепочке) | ZNI_INIT |
| REL | Ночной релиз (окно) | ZNI_DONE |

## Цепочка этапов (порядок)

1. FF — Передача тестовых сборок на тестирование  
2. ZNO_DOCS — Документы для ЗНО  
3. ZNO_INIT — Создание ЗНО  
4. ZNO_DONE — Выполнение ЗНО  
5. ZNI_DOCS — Документы для ЗНИ (Code freeze)  
6. ZNI_INIT — Создание ЗНИ  
7. ZNI_DONE — Выполнение ЗНИ (дата релиза)

## Сдвиги между этапами (календарные дни)

Выходные **не исключаются**: +N означает прибавить N к календарной дате.

| От | К | Сдвиг |
|----|---|-------|
| FF | ZNO_DOCS | +2 если INT=false, +4 если INT=true |
| ZNO_DOCS | ZNO_INIT | +1 |
| ZNO_INIT | ZNO_DONE | +0 |
| ZNO_DONE | ZNI_DOCS | +7 если PSY или NT, иначе +1 |
| ZNI_DOCS | ZNI_INIT | +1 |
| ZNI_INIT | ZNI_DONE | +2 |

Флаги релиза: INT, PSY, NT (хранятся в `releases.flag_int`, `flag_psy`, `flag_nt`).

## Режимы расчёта

### От FF вперёд (fromFF)

- Вход: дата/время FF  
- Для каждого следующего этапа: предыдущая дата + сдвиг (календарные дни)  
- Время нормализуется в рабочий день 09:00 (Пн–Пт; иначе сдвиг на следующий понедельник 09:00)  
- Для ZNI_DONE (REL) после расчёта применяется **техокно** (см. ниже)

### От релиза назад (fromREL)

- Вход: окно релиза (начало и/или конец); якорь — **конец окна** для ZNI_DONE (дата/время как ввёл пользователь)  
- Обратный проход: вычитание сдвигов по цепочке (календарные дни)  
- Для промежуточных этапов: 09:00; если день попал на Сб/Вс — сдвиг на **предыдущую пятницу** (не вперёд на понедельник)  
- Техокно для backward **не** применяется

## Техокна релиза (только forward после расчёта ZNI_DONE)

Допустимые ночные окна: **Пн→Вт**, **Ср→Чт**, **Сб→Вс** (старт вечером в день Пн / Ср / Сб).

Правило сдвига на ближайшее окно:

- дата на **Вт** → сдвиг на **Ср** 09:00  
- дата на **Чт** → сдвиг на **Сб** 09:00  
- иначе → ближайший следующий старт: Пн, Ср или Сб (09:00)

Реализация: `src/services/scheduling/techWindows.ts`

## API

- POST `/api/releases/:id/schedule/preview` — расчёт suggested, сохранение флагов  
- POST `/api/releases/:id/schedule/apply` — сохранение planned/suggested в `release_stages`  
- GET `/api/releases/:id/stages` — список сохранённых этапов  
- PATCH `/api/release-stages/:id` — ручное обновление статуса/факта

## Примеры для ручной проверки

1. FF = пятница, INT=false: ZNO_DOCS = FF + 2 календарных дня = воскресенье (нормализация может сдвинуть на Пн 09:00).  
2. ZNO_DONE → ZNI_DOCS: при PSY=true сдвиг +7 календарных дней.  
3. Forward: если ZNI_DONE попадает на вторник — сдвиг на среду (окно Ср–Чт).
